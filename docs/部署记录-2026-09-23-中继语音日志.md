### 2.1 音频输入源确认

- 3.5mm 座 **P21**（四段 CTIA）：PIN1 = `LMIC_P`（左声道 MIC 输入）
- 板载麦 **P20** = `RMIC_P`（右声道）
- NAU88C22 内部输入源开关：`Main Mic` / `Headset Mic`，当前 `Headset Mic [on]`、`Main Mic [off]`

- 因此录音固定取**左声道**（`vlog_channel=left`），并在软件里做成可切换项

## 4. 关键实现说明

### 4.1 录音状态机（`Recorder`）

- **触发**：`BUSY_STATE['active']` 或 `PTT_LEVEL` 任一为真
- **pre-roll**：空闲时环形缓冲保留最近 `vlog_pre_roll` 秒（默认 3 s），触发瞬间补写到分段头部
- **尾音**：状态结束后继续录 `vlog_post_roll` 秒（默认 2 s）；尾音阶段**不再按类型切段**
- **分段**：同一会话内状态组合变化（只收 / 只发 / 收发同时）切成独立分段，共享 `session_id`
- **单段上限**：默认 300 s，超长自动切段
- **抖动过滤**：短于 `vlog_min_seconds`（默认 1.0 s）的记录默认**只计数不落盘**，避免日志被静噪毛刺淹没
- 落盘格式：16 kHz / 单声道 / PCM16 WAV

### 4.2 非语音不送 ASR

silero VAD（`/opt/ai/asr/silero_vad.onnx`，从 sherpa-onnx release 下载）先把整段切成语音句，
**只有语音句才送 SenseVoice**。非语音按频谱特征细分：

| 类别 | 判据 |
|---|---|
| `jitter` | 时长 < `vlog_min_seconds` |
| `silence` | dBFS ≤ `vlog_silence_dbfs`（默认 −48） |
| `aprs` | 无语音 且 `tone_ratio`（1100–1300 Hz + 2100–2300 Hz 能量占比，Bell202 mark/space）≥ 0.45 |
| `tone` | 无语音 且 频谱平坦度 ≤ 0.25（单音/信标） |
| `noise` | 其余 |

这样避免了 SenseVoice 对噪声产生幻觉（如"谢谢观看"）。

### 4.3 本地 LLM 按需启停（重要）

**实测 `rkllm-server` 常驻占 2.29 GB RSS / 1.6 GB dma-buf 共享内存**，
在 3.8 GB 总内存 + 1080p 录像 + ASR 的场景下会把可用内存压到 ~300 MB。
因此改成**按需加载 + 空闲卸载**：

- `systemctl is-active` **不可靠**：单元是 `Type=simple`，进程一起来就报 active，
  但模型还没加载完、8001 端口没绑定 → 必须用 **HTTP 探活**（`/v1/models`）
- 跨进程用 **文件租约** `/tmp/elf2-llm-lease` 协调：使用方续期，卸载方只在不持有租约时才停
- 免密：`/etc/sudoers.d/99-elf2-rkllm` 只放行 `systemctl {start,stop,restart,is-active} rkllm-server`
- 网页 LLM 对话 / Agent 对话在本地 provider 下会**自动拉起**模型

### 4.4 每日总结

- 默认 `vlog_summary_time=23:30`（可在设置页改），调度线程每 25 s 检查一次
- 默认 `vlog_summary_provider=auto`：**短文本走本地**，**>5000 字且配了外部 Key 时走 DeepSeek**
- 分块：本地 2200 字/块，外部 12000 字/块；**单块直接采用 map 结果**（避免小结被 reduce 弄坏）
- 多块：分层归并（本地合并阈值 3000 字），最多 3 层
- 本地模型打满上下文会直接返回空串 → `llm_chat` 检测到空输出会**截断到 60% 重试一次**

## 7. 构建过程中发现并修复的真实缺陷

| # | 现象 | 根因 | 修复 |
|---|---|---|---|
| 1 | 本地 LLM 800 字以上提示词**空输出** | `flask_server.py` 硬编码 `max_context_len = 512`（可用仅 508 token） | 改为读环境变量 `RKLLM_MAX_CONTEXT`，systemd drop-in 设为 **4096**；实测 3015 字提示词可正常总结 |
| 2 | 提升上下文后 `rkllm-server` 被 **SIGKILL** | `RKNPU: failed to get pages: -12` → OOM；但复测发现真凶是**残留 root 进程占内存**，清理后 512/1024/2048/3072/4096 全部正常 | 清理残留 + 加 4 GB NVMe swap（swappiness=10）+ `min_free_kbytes=64 MB` |
| 3 | `rms`/`peak` 入库为 0、`dbfs` 正数 | `analyze()` 用浮点标度（0~1）覆盖了 int16 标度；`_close_segment` 的 dBFS 少除 32768 | `analyze()` 统一乘 32768 入库，dBFS 用浮点算 |
| 4 | 日报生成到一半服务被停 | 网页服务的空闲卸载线程与一次性脚本**互不可见** | 引入跨进程文件租约 `/tmp/elf2-llm-lease` |
| 5 | 首请求 `Connection refused` | `systemctl is-active` 在 `Type=simple` 下过早返回 active | 改为轮询 HTTP `/v1/models` 就绪 |
| 6 | 单块日报输出"请提供时段2到时段N" | 本地 1.5B 指令跟随弱 + 复杂 prompt 打退堂鼓 | 简化 prompt；单块跳过 reduce；多块分层归并 |
| 7 | 本地 reduce 提示词会撑爆上下文 | 4096 token ≈ 5600 中文字，而阈值设了 6000 字 | 阈值收到 3000 字（块 2200 字）+ 空输出截断重试 |

## 10. 待办 / 已知限制

1. **需要真实电台音频实测**：目前只用 BUSY 极性翻转 + piper 合成语音验证过。
   需要用真实通联确认：① BUSY 边沿能否正确起停录 ② 真机语音（300–3000 Hz 带限 + 压缩）的识别率
   ③ 前后滚时长是否需要调整。
2. **呼号识别准确率低**：`BG7KHI`→"曾"、`BI7KHI`→"曾给"。SenseVoice 对字母串较弱；
   后续可考虑（a）换用支持热词的 transducer 模型（b）对识别文本做呼号词典纠错（c）ASR 语言固定为 zh。
3. **实时对讲的"停止"按钮**：语音日志启用时不会真的停采集中枢（录音依赖它），
   界面会返回提示文案；若需要彻底停止，应先关掉 `vlog_enabled`。
4. **`vlog_min_seconds` 默认丢弃抖动片段**：与"保留全部"的取舍，可用 `vlog_keep_transient=1` 改成全保留。
5. 本地 LLM 上下文受限于 **4096 token**（模型转换时的上限），超长日报需要更多层归并；
   若要更大上下文需用 RKLLM Toolkit 重新转换模型。
