# APRS 收发子系统部署记录（2026-09-23）

> **EN** — APRS subsystem for the ELF2/RK3588 relay: a from-scratch pure-Python
> 1200 bps Bell 202 software TNC for receive, APRS packet generation for transmit
> (weather / telemetry / position / status / message), carrier-sense arbitration
> that reuses the existing PTT GPIO, and a new `/aprs` page with a Tianditu
> basemap. No digipeater, no iGate, no query responses by design.

## 2. 为什么必须自研 TNC（硬件约束决定架构）

NAU88C22 的 **capture 通道是独占的**——第二路 `arecord` 会直接
`Device or resource busy`。这意味着：

- **Direwolf 这类独立 TNC 进程无法直接开声卡**，必须改成从管道喂音频，多一层故障点；
- 正确做法是**挂在已有的单一声道采集中枢上**：`app.py` 的 `_mic_capture_loop`
  已经在把每个 4096 字节（16kHz 立体声 = 1024 帧）块交给 `voice_service.feed()`，
  APRS 只是在这个位置并列再喂一次。

同时**不能依赖 BUSY 触发**：实测 APRS 爆发紧跟话音尾部，`#51` 的 APRS 落在
**8.72 s** 而录音总长 11.25 s，余量只有 2.5 s。依赖 BUSY 分段和 2 s 尾音必然漏包。
因此 TNC 是**常驻连续解码**的，成本实测 **约 2.6% 单核**（114 s 音频耗 2.94 s CPU）。

## 3. 协议栈

```
音频(16kHz 单声道)
  → 带通 300–3600 Hz（流式 IIR，带状态）
  → 双音相关：W=round(16000/1200)=13 样本矩形窗 × {1200, 2200} Hz
  → 判决变量 d[n] = |y1200|² − |y2200|²
  → 双音纯度 ratio = (|y0|²+|y1|²)/(W·Σx²)  ⇒ 突发检测
  → 突发窗内做 64 相位 × 2 极性搜索
  → NRZI 解码 → HDLC 去填充/标志定界 → AX.25 拆帧 → CRC-16/X-25 校验
```

**正确性判据是 CRC 校验通过**，不是能量或相似度，所以误报率极低；突发检测只用来省 CPU。

关键实数：纯 AFSK 的 `ratio ≈ 0.5`，白噪声 `≈ 2/W = 0.154`，实测阈值窗内
max_ratio 为 **0.61**，噪声段不会超过 **0.30**。

## 4. 调试过程中修掉的 9 个真 bug

这些都是"看起来能跑但结果错"的问题，记录下来避免重犯：

1. **HDLC 收尾标志被误判成中止序列**
   收尾标志 `01111110` 含 6 个连续 1，而标准的去填充规则是"5 个 1 后必为 0"。
   若先做去填充判定，正常收尾会被当成 abort 丢掉帧。**标志检查必须早于去填充**。

2. **自检脚本漏了 NRZI 编码**
   `modulate()` 期望的是 NRZI *电平*序列，测试却直接塞了 HDLC *位*序列。
   现象是"干净合成信号也解不出来"，一度误判为解调器坏了。

3. **Bell 202 极性反了**
   标准：mark（电平 1）= **1200 Hz**，space（电平 0）= 2200 Hz。调制器发反了。

4. **带时间戳位置报文解析错位（最严重）**
   `/` 与 `@` 报文在纬度**前面**还有 7 字符时间戳（`DDHHMMz`）。按无时间戳的
   偏移去读 `body[0:8]`，会把时间戳当成纬度前两位，**解出完全错误的坐标**。

5. **突发必须在「追加时」就合并**
   采集每块只有 1024 样本，一个 0.9 s 的 APRS 突发会被切成几十个分片。
   若在消费端（`_service_bursts`）再合并，每次只有一个分片"够旧"被消费出去，
   **合并永远不发生**，于是每片各搜一次、而每个窗口（1024+2×4800）都装不下
   完整帧（13800 样本）——现象是**"能测到突发却一帧都解不出来"**。

6. **尾部余量导致纯突发信号永不处理**
   原设计等尾部 0.30 s 样本到齐才解突发；离线分析纯突发（无尾音）时永远等不到。
   改为余量 0.12 s 并提供 `flush()`。

7. **气象站离线时发了不含气象字段的「气象包」**
   接收方会看到一条名义上是 `_WX` 却没有任何测量值的记录，比不发更糟。
   现在直接取消发射并返回原因。

8. **路径字段误用**：`parse_path()` 返回 `(呼号, SSID)` 元组，
   `('WIDE1-1', 1)` 会显示成 `WIDE1--1`。正确写法是 `('WIDE1', 1)`。

9. **`.grid-4` 在 `app.css` 里并不存在**（只有 `.grid-2`/`.grid-3`）
   → 指标卡退化成单列堆叠。连带发现**早先交付的语音日志页也有同样问题**，一并修复。

## 5. 灵敏度实测与参数选择（用真实录音说话）

用 10+ 段真实中继录音做对比实验，判据是"能否解出 APRS"：

| 解调变体 | 解出文件数 |
|---|---|
| 带通 **400–3400** Hz（初版） | **1**（只有 `#51`） |
| 带通 **300–3600** Hz（现版） | **2**（`#51` + `#46`） ✅ |

窄带会削掉 2200 Hz 音调的边带与时钟分量，对贴地信号是致命的。
**最终采用 300–3600 Hz。**

回归验证（流式 TNC，按采集中枢 1024 样本/块喂入）：

```
vlog_221421_rx_00.wav  t=7.82s  APN000,BI7KHI,WIDE1-1,WIDE2-1  dtype=status  INFO='>'
vlog_222607_rx_00.wav  t=8.72s  APN000,BI7KHI,WIDE1-1,WIDE2-1  dtype=status  INFO='>'
```

两条独立录音解出同一包，与批处理探针结论**完全一致**，证实流式路径正确。

合成信号自检（`aprs_service.py` 直接运行即为自检）：

```
CRC 标准向量 b"123456789" -> 0x906E ✓
5 种报文 × 3 种采样率(8000/16000/48000)  全部 EXACT 还原
SNR 20/10/6/3/0 dB（含 1.5 s 语音前导）  全部解出
```

## 6. 报文能力

**接收解析**：位置（未压缩/压缩/Mic-E 保留原文）、气象（`_ddd/sss` `g` `t` `r` `p`
`P` `h` `b` `s`）、状态 `>`、遥测 `T#`、消息 `:`、对象 `;`、物品 `)`、查询 `?`、
NMEA `$`、自定义 `{`。**未知类型也原样入库，永不丢数据。**

**发射生成**：

| 类型 | 格式 | 数据源 |
|---|---|---|
| 位置信标 | `!` / `/` 未压缩经纬度 + 符号 + 注释 | 本站坐标（手填 / NMEA） |
| 气象包 `_WX` | `@` 时间戳位置 + 气象后缀 | **已有 Modbus 气象站**（`/dev/ttyS9`） |
| 遥测 `T#` | `T#SSS,a1..a5,dddddddd` | 5 路模拟量可配置（默认电池/光伏/CPU温度/发射计数/风速） |
| 状态 `>` | `>text` | 设置项 |
| 文本消息 | `:ADDRESSEE:text{id` | 网页输入 |

单位换算按 APRS 规范：风速 m/s→mph、温度 ℃→℉、雨量 mm→1/100 英寸、气压 hPa→0.1hPa。

## 7. 发射链路与信道仲裁

```
抢 tx_lock → 最短间隔检查 → 载波侦听 → 组帧 → 生成 AFSK → _ptt_retain()
  → 等 0.12s 功放稳定 → 抢占声卡(aplay 原始 PCM) → 播放 → _ptt_release()
```

**载波侦听（关键）**：检测到 BUSY 有效或本机 PTT 正忙就暂缓，信道空闲后再随机
延迟 `aprs_defer_jitter`（默认 3 s）才发；超过 `aprs_defer_max`（默认 120 s）则
放弃本次并记录。这不只是礼貌问题——**语音与 AFSK 叠加会让两边都解不出来**，
而实测 APRS 本来就贴着话音尾部，撞上的概率很高。

复用已有 PTT 设施：`PTT_GPIO_NUM=97`（GPIO3_A1）、`PLAY_LOCK`、`_stop_proc`、
最短压发保护、事件环形缓冲。

## 8. 地图选型与合规（重要）

### 结论：使用天地图，不使用 OSM

| 方案 | 坐标系统 | 能否直接画 APRS 的 WGS-84 | 合规 |
|---|---|---|---|
| **天地图**（国家地理信息公共服务平台） | **CGCS2000** | ✅ 差 <1 m，**无需转换** | 官方平台，地图已审核自带审图号，资质由平台承担 |
| 高德 | GCJ-02 | ❌ 偏移 **约 300–600 m** | 需实名，有配额 |
| 百度 | BD-09 | ❌ 偏移更大，需二次转换 | 需实名 |
| OSM | WGS-84 | ✅ | ❌ **国界/台湾/南海诸岛画法不符合《公开地图内容表示规范》**；官方 Tile Usage Policy 禁止批量下载；**本网络内 `tile.openstreetmap.org` 实测 TIMEOUT** |

**合规要点**：在境内提供互联网地图服务需要**测绘资质 + 地图审核（审图号）**。
个人项目不可能自行申请，唯一正确做法是使用持证服务商的地图 API，把审核责任转移给平台。
APRS 报文里是 WGS-84，天地图是 CGCS2000，两者实用精度一致，因此可以直接绘制；
若用高德/百度而不做 GCJ-02/BD-09 转换，**中继台在地图上会偏到隔壁街区**。

### 天地图 key 分两种权限类型（实测确认）

```
服务端 key（无 Referer）: 板子 & PC 均 200 OK   → 供板端代理取瓦片
浏览器端 key（带 Referer）: 200 OK              → 只能浏览器直连
浏览器端 key（无 Referer）: 403 {"code":301012,"msg":"权限类型错误"}
```

本项目**默认走板端代理 + 磁盘缓存**（服务端 key），好处有三：

1. key 只存在板子上，不出现在前端；
2. 瓦片落盘缓存（默认上限 512 MB），**断网时已浏览过的区域仍能显示**；
3. 代理接口受登录保护，避免 key 被公开滥用。

图层实测：`img_w`/`cva_w`/`vec_w` 返回 **JPEG**，`ter_w` 返回 **PNG** ——
代理必须透传响应头里的真实 MIME，**不能写死**。

### 位置来源抽象

`PositionProvider` 支持 `manual`（设置里手填固定坐标）与 `nmea`（串口 GPS）。
**后续接入 ZED-F9P RTK 基准站时，只需把 `aprs_pos_source` 改成 `nmea`
并填 `aprs_gps_port`，其余代码（信标/气象/遥测）无需改动**——NMEA GGA/RMC 解析已实现。

## 9. 部署步骤

```bash
# 1) 安装模块与页面
sudo install -m 644 -o elf -g elf aprs_service.py /www/aprs_service.py
sudo install -m 644 -o elf -g elf aprs.html /www/templates/aprs.html
sudo install -m 644 -o elf -g elf aprs.js   /www/static/js/aprs.js
sudo install -m 644 -o elf -g elf aprs.css  /www/static/css/aprs.css
mkdir -p /www/static/vendor/leaflet/images
curl -o /www/static/vendor/leaflet/leaflet.js  https://unpkg.com/leaflet@1.9.4/dist/leaflet.js
curl -o /www/static/vendor/leaflet/leaflet.css https://unpkg.com/leaflet@1.9.4/dist/leaflet.css

# 2) 打 app.py 集成补丁（幂等，带锚点断言）
python3 deploy/patch_app_aprs.py /www/app.py
python3 -m py_compile /www/app.py

# 3) 打 base.html 导航补丁：在「语音日志」后加一行
#    <a class="tab-btn nav-link" href="{{ url_for('aprs_page') }}">APRS</a>

# 4) 瓦片缓存目录 + 重启
sudo mkdir -p /opt/ai/aprs_tiles && sudo chown elf:elf /opt/ai/aprs_tiles
sudo systemctl restart relay-web
```

**注意**：Windows 上编辑的文件全是 CRLF，装到板子上前必须
`sed -i 's/\r$//'`，否则 Python/shebang 会出问题。

## 11. 已知限制与后续

1. **Mic-E 报文只保留原文不解析经纬度**。Mic-E 把经纬度编码在目的地址里，
   各实现细节有分歧；为避免显示错误坐标，当前只存原文。若实测中出现大量 Mic-E
   报文（Kenwood/Yaesu 手台常见），再补解析。
2. **压缩位置只解经纬度与符号**，`cs_raw`（航向/速度或高度域）原样保留不猜测。
3. **不做 digipeater / iGate**（按需求），也不响应 `?WX?` 查询。
4. **天地图瓦片缓存上限 512 MB**，超过按最旧优先清理。
5. 气象站暂无风向与气压字段时，APRS 气象包会省略对应项（规范允许）。
6. **`ter_w` 地形层是 PNG**，代理已按响应头透传，但若将来新增图层需注意。
