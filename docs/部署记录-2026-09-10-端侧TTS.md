## 5. 自动朗读无声问题排查记录

人工测试“你好”后 LLM 回复正常，但 3.5mm AUX 没有声音。排查结果：

- `/api/tts/speak` 请求实际已触发，并生成 WAV 文件；
- `aplay` 进程也正常启动；
- 使用 `amixer -c 1` 检查发现 `Headphone` 和 `Speaker` 音量为 0%，且 Playback 为 `off`；
- 即 **软件合成与播放链路正常，但 NAU88C22 输出混音器被静音**。

修复：

```bash
amixer -c 1 sset 'Headphone' 80% unmute
amixer -c 1 sset 'Speaker'   80% unmute
sudo alsactl store
```

并在 `app.py` 中增加 `_ensure_audio_unmuted()`：

```python
# 每次启动及播放前确保 Headphone / Speaker 没有静音
amixer -c 1 sset Headphone 80% unmute
amixer -c 1 sset Speaker   80% unmute
```

修复后再次测试：

```text
POST /api/tts/speak -> 200
aplay -D plughw:CARD=rockchipnau8822,DEV=0 ...
Headphone Playback [on]
Speaker Playback [on]
```

## 6. 流式即时朗读（新增）

为避免等待 LLM 整段输出后再朗读，已实现流式 TTS：

- 前端：
  - LLM 流式 token 到达时持续累积；
  - 遇到 `。！？!?；;` 或换行立即切分；
  - 长句无标点时按逗号/空格/80 字切分；
  - 通过 `/api/tts/stream/chunk` 逐段提交。
- 后端：
  - 每个朗读会话维护文本队列和播放队列；
  - 合成线程负责 Piper 合成下一个片段；
  - 播放线程负责 `aplay` 串行播放当前片段；
  - 当前段播放时，下一段已在合成，减少等待间隔。
- 实测日志确认：
  ```text
  POST /api/tts/stream/start 200
  POST /api/tts/stream/chunk 200
  POST /api/tts/stream/chunk 200
  POST /api/tts/stream/chunk 200
  POST /api/tts/stream/end   200
  ```
  多个 chunk 在 LLM 结束前就已提交并开始播放。
