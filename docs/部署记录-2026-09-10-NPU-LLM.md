# ELF2/RK3588 NPU LLM 部署记录（Qwen2.5-1.5B W8A8）

> 时间：2026-09-10
> 目标设备：ELF2/RK3588，`192.168.101.206`，Ubuntu 22.04.5 LTS，kernel 5.10.209
> 目的：将 CPU llama.cpp 推理迁移到 RKNPU 上运行，并验证 NPU LLM 服务可用于后续部署。

## 1. 结论

- 板卡已具备完整 RKNPU 运行环境：
  - `CONFIG_ROCKCHIP_RKNPU=y`
  - `dmesg` 显示 `RKNPU fdab0000.npu ... rknpu 0.9.8`
  - `/dev/dri/renderD129` 为 NPU 对应的 DRM render 节点
  - `/usr/lib/librknnrt.so` 版本 2.1.0
  - `/usr/lib/librkllmrt.so` 版本 **RKLLM SDK 1.1.4**
- 已部署 RKLLM + Qwen2.5-1.5B-Instruct RK3588 W8A8 模型，运行在 NPU。
- 已通过 HTTP API 回环测试，服务运行在 `http://192.168.101.206:8001/v1/chat/completions`。
- 已创建 systemd 服务 `rkllm-server.service`，开机自启。
- CPU `llama-server.service` 已停止并取消自启，保留作为 fallback。

## 4. HTTP 服务部署

### 4.1 启动命令

```bash
cd /opt/ai/rkllm-server
python3 flask_server.py \
  --rkllm_model_path /opt/ai/models/qwen2.5-1.5b-instruct-rk3588-w8a8.rkllm \
  --target_platform rk3588
```

### 4.2 systemd 服务

`/etc/systemd/system/rkllm-server.service`：

```ini
[Unit]
Description=RKLLM NPU LLM Server (Qwen2.5-1.5B RK3588 W8A8)
After=network.target

[Service]
Type=simple
User=elf
WorkingDirectory=/opt/ai/rkllm-server
Environment=LD_LIBRARY_PATH=/usr/lib
Environment=RKLLM_LOG_LEVEL=1
ExecStart=/usr/bin/python3 /opt/ai/rkllm-server/flask_server.py --rkllm_model_path /opt/ai/models/qwen2.5-1.5b-instruct-rk3588-w8a8.rkllm --target_platform rk3588
Restart=on-failure
RestartSec=5
TimeoutStartSec=180

[Install]
WantedBy=multi-user.target
```

启用/查看：

```bash
sudo systemctl enable rkllm-server
sudo systemctl restart rkllm-server
systemctl status rkllm-server
```

## 5. 说明与后续建议

1. 当前板卡 3.7GB RAM，Qwen2.5-1.5B W8A8 是较稳妥的 NPU 模型规格；3B W8A8 约 3.7GB，内存不足，暂不建议直接加载。
2. 如需更高模型质量，可选路线：
   - 在 PC 端用 RKLLM-Toolkit 将 Qwen2.5-3B/7B 转成更低比特的 RK3588 专用量化模型；
   - 增加板卡内存/启用足够 zram/swap 后尝试 3B W4A16；
   - 或将复杂问题转发到外部 API，端侧 NPU 负责低延迟常规任务。
3. 现有 Flask 服务适合内网联调；生产部署建议改为 gunicorn/waitress，并加 API Key/JWT。
4. `fix_freq_rk3588.sh` 中的 sudo 调用已在服务代码中跳过；当前 NPU 工作频率为 `1000000000Hz`。

## 6. Deepseek Harness / OpenAI 兼容补充（2026-09-10）

原先服务只有 `/rkllm_chat` 与 `/v1/chat/completions`，Deepseek Harness 在“测试模型”阶段可能先请求根路径或 `/v1/models`，因此出现 404。已补全：

| 路径 | 方法 | 说明 |
|---|---|---|
| `/` | GET | 服务信息 |
| `/health`、`/v1/health` | GET | 健康检查 |
| `/v1/models`、`/models` | GET | OpenAI 风格模型列表 |
| `/v1/chat/completions` | POST | OpenAI Chat Completions |
| `/chat/completions` | POST | 兼容不带 `/v1` 的 Base URL |
| `/rkllm_chat` | POST | RKLLM 原生接口 |

同时将流式输出改为标准 SSE：

```text
data: {"id":"chatcmpl-...","object":"chat.completion.chunk",...}
data: [DONE]
```

建议 Deepseek Harness 填写：

```text
API Base URL: http://192.168.101.206:8001
Model: qwen2.5-1.5b
```

如果 Harness 强制要求 Base URL 带 `/v1`，也可填写：

```text
http://192.168.101.206:8001/v1
```

因为 `/v1` 会分别拼接为 `/v1/models` 与 `/v1/chat/completions`，两者都已支持。
