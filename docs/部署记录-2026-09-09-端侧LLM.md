# ELF2 端侧 LLM 部署与回环测试记录

> 时间：2026-09-09
> 目标设备：ELF2/RK3588，`192.168.101.206`
> 系统：Ubuntu 22.04.5 LTS，kernel 5.10.209，aarch64
> 内存：3.7 GiB；AI 数据盘：NVMe 128G，挂载于 `/opt/ai`

## 1. 部署结果摘要


| 项目          | 值                                                 |
| --------------- | ---------------------------------------------------- |
| LLM Runtime   | llama.cpp（源码编译，CPU）                         |
| 模型          | Qwen2.5-1.5B-Instruct-GGUF`q4_k_m`                 |
| 模型路径      | `/opt/ai/models/qwen2.5-1.5b-instruct-q4_k_m.gguf` |

| HTTP 服务地址 | `http://192.168.101.206:8001`                      |

> 说明：当前系统未看到 `/dev/rknpu`，因此本次先用 **CPU llama.cpp** 完成可用性部署。后续若启用 RKNPU 驱动，可再评估 RKLLM/rkllama 将同一模型或更合适的小模型跑到 NPU 上。

## 2. 部署步骤

```bash
# 安装 cmake
sudo apt-get update
sudo apt-get install -y cmake

# 下载 llama.cpp 源码（GitHub clone 不稳定时改用 codeload tarball）
cd /opt/ai
curl -L -o /tmp/llama.cpp-master.tar.gz \
  https://codeload.github.com/ggml-org/llama.cpp/tar.gz/refs/heads/master
tar -xzf /tmp/llama.cpp-master.tar.gz -C /opt/ai
mv /opt/ai/llama.cpp-master /opt/ai/llama.cpp

# 编译（内存 3.7G，建议 -j2）
cd /opt/ai/llama.cpp
cmake -B build -DCMAKE_BUILD_TYPE=Release \
  -DLLAMA_CURL=OFF \
  -DLLAMA_USE_PREBUILT_UI=OFF \
  -DLLAMA_BUILD_UI=OFF \
  -DLLAMA_BUILD_SERVER=ON
cmake --build build --config Release -j2

# 下载 Qwen2.5-1.5B-Instruct GGUF q4_k_m
cd /opt/ai/models
curl -L -o qwen2.5-1.5b-instruct-q4_k_m.gguf \
  'https://modelscope.cn/models/Qwen/Qwen2.5-1.5B-Instruct-GGUF/resolve/master/qwen2.5-1.5b-instruct-q4_k_m.gguf'
```

## 3. systemd 服务

服务文件：`/etc/systemd/system/llama-server.service`

```ini
[Unit]
Description=llama.cpp OpenAI-compatible server for Qwen2.5-1.5B
After=network.target

[Service]
Type=simple
User=elf
WorkingDirectory=/opt/ai
ExecStart=/opt/ai/llama.cpp/build/bin/llama-server -m /opt/ai/models/qwen2.5-1.5b-instruct-q4_k_m.gguf --host 0.0.0.0 --port 8001 -c 2048 -t 4
Restart=on-failure
RestartSec=3

[Install]
WantedBy=multi-user.target
```

启用：

```bash
sudo systemctl daemon-reload
sudo systemctl enable llama-server
sudo systemctl restart llama-server
systemctl status llama-server
curl http://127.0.0.1:8001/health
```

## 4. CLI 回环测试

```bash
/opt/ai/llama.cpp/build/bin/llama-cli \
  -m /opt/ai/models/qwen2.5-1.5b-instruct-q4_k_m.gguf \
  -p '你好，请简单介绍一下你自己。' \
  -n 96 -c 1024 -t 4 --temp 0.7 -st
```

输出示例：

```text
你好！我是阿里云的大规模语言模型，我叫通义千问。我是一个通用的大规模语言模型，
能够理解和生成人类的语言。……
[ Prompt: 50.8 t/s | Generation: 22.2 t/s ]
```

## 5. HTTP API 回环测试

```bash
curl http://127.0.0.1:8001/v1/chat/completions \
  -H 'Content-Type: application/json' \
  -d '{
    "model":"qwen2.5-1.5b",
    "messages":[
      {"role":"system","content":"你是智能无线电中继助手，回答应简短。"},
      {"role":"user","content":"当前电池电压低，请给出建议。"}
    ],
    "max_tokens":80,
    "temperature":0.3
  }'
```

返回：

```json
{
  "choices": [
    {
      "message": {
        "role": "assistant",
        "content": "请充电或更换电池。"
      }
    }
  ]
}
```

观测性能：prompt 约 49~50 t/s，生成约 22 t/s，单次短答复延迟约 300~400ms，满足后续中继智能控制/文本服务的基本需求。

## 6. 下一阶段建议

1. 在 `/opt/ai` 规划 `radio-daemon`、`ai-orchestrator`、`asr-tts` 等子目录；
2. 对接中继接收音频链路：ALSA 采集 → RNNoise/Silero VAD → sherpa-onnx ASR → 本服务的 OpenAI 兼容 API；
3. 需要 NPU 时：启用 `/dev/rknpu` 驱动，再评估 RKLLM-Toolkit/rkllama 转换部署；
4. 服务端口建议后续用 FRP/Nginx 暴露，并加 API Key/JWT。
